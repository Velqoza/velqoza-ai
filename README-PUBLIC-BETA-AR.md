# VELQOZA AI — دليل نشر Beta آمنة نسبياً

## التحذير قبل النشر
هذا تحديث تقوية أمنية **وليس شهادة أمان أو جاهزية 100%**. لا تنشر للجميع قبل اختبار النشر، توفير نسخ احتياطية، ووضع حدود إنفاق للمزوّد. لا ترفع ملفات `.env` أو `*.sqlite*` إلى GitHub مطلقاً.

## أهم التغييرات
- مسارات `/api/ai/generate` و`/api/ai/edit` تحتاج تسجيل دخول.
- حدود يومية لكل حساب في SQLite، إضافة إلى حدود IP، لمنع الاستهلاك المفتوح. الحدود تُحسب للمحاولات حتى لو فشلت.
- في الإنتاج تسجيل الحسابات **بدعوة** افتراضياً، ويمكن فتحها عبر `ENABLE_PUBLIC_SIGNUP=true` بعد مراجعة التكاليف والأمان.
- إخفاء نصوص أخطاء المزوّد من الاستجابات العامة، وإضافة `Cache-Control: no-store` للـ API.
- تعطيل التشغيل الإنتاجي إذا لم يتوفر مفتاح/سر JWT/مسار قاعدة بيانات مطلق/دومين HTTPS.
- تقديم واجهة React المبنية مباشرة من Express على نفس الدومين في وضع الإنتاج.
- `.gitignore` يمنع ملفات SQLite وقواعد البيانات والبيانات المحلية.

## تجربة محلية (Windows)
1. احتفظ بنسخة منفصلة من مجلدك القديم وملف SQLite مع WAL/SHM عند الحاجة **بعد إيقاف البرنامج**. لا تستبدل قاعدة بياناتك الحالية بلا نسخة احتياطية.
2. فك ZIP إلى مجلد جديد، وانقل فقط الإعدادات الخاصة بك إلى `.env` (لا تنشرها).
3. افتح CMD داخل `velqoza-ai` وشغّل: `npm.cmd install`، ثم `npm.cmd run dev`.
4. جرّب: تسجيل الدخول القديم، إنشاء/تعديل مشروع، حفظه، إعادة فتحه، محادثة، تصدير ZIP.
5. للتأكد من حماية الـ AI: طلب غير موثق لـ `POST /api/ai/generate` يجب أن يرجع HTTP 401.

## نشر تجريبي على Render (خدمة واحدة)
> SQLite يتطلب قرصاً دائماً مدفوعاً أو مزوّداً آخر يدعم تخزيناً دائماً. Render غير المدفوع لا يحفظ SQLite بشكل دائم.

1. ارفع المصدر إلى **مستودع GitHub خاص** بعد التأكد أن `.env` وملفات قواعد البيانات غير موجودة في Git history.
2. أنشئ Render Web Service من المستودع: Runtime Node، أوامر البناء `npm ci && npm run build`، أمر التشغيل `npm start`.
3. أضف Persistent Disk بمسار `/var/data`، واضبط `DATABASE_PATH=/var/data/velqoza.sqlite`.
4. اضبط Variables سرية على Render وليس داخل المستودع:
   - `NODE_ENV=production`
   - `OPENAI_API_KEY=<your_private_key>`
   - `OPENAI_MODEL=<a_model_available_to_your_account>`
   - `JWT_SECRET=<cryptographically_random_32_plus_character_secret>`
   - `CLIENT_ORIGIN=https://ai.velqoza.com` (استخدم الدومين الفعلي بعد ربطه)
   - `DATABASE_PATH=/var/data/velqoza.sqlite`
   - `ENABLE_PUBLIC_SIGNUP=false`
   - `BETA_INVITE_CODE=<strong_private_invite_code>`
   - `DAILY_GENERATE_LIMIT=3`, `DAILY_EDIT_LIMIT=8`, `DAILY_STUDIO_LIMIT=25`
5. ربط الدومين وHTTPS واختبار الموقع على جوال آخر بدون بيانات حقيقية. يُدخل رمز الدعوة في نافذة إنشاء الحساب فقط.
6. **لا تنسخ قاعدة بياناتك المحلية للحساب الشخصي على الموقع العام** إلا إذا كنت تريد نشر تلك البيانات؛ الأفضل قاعدة بيانات جديدة منفصلة للحسابات العامة.
7. حدد ميزانية OpenAI ومراقبة الاستهلاك من مزوّد API. حدود الحساب اليومية ليست سقف إنفاق مضموناً، ويمكن تجاوزها بإنشاء حسابات أو طلبات مكلفة.

## فحوص لا بد منها قبل فتح التسجيل للجميع
- اختبار npm audit بعد تثبيت المكتبات، ومعالجة الثغرات المؤكدة دون تحديثات عمياء تكسر المشروع.
- إجراء اختبار أمني مستقل ومراجعة OWASP، وحماية الحسابات من إساءة التسجيل (تأكيد البريد/تحقق آلي عند الحاجة).
- إضافة استعادة كلمة المرور، سياسة خصوصية وشروط استخدام، ووسيلة حذف حساب وبيانات.
- مراقبة الاستهلاك والفواتير والتنبيهات، نسخ احتياطي تلقائي SQLite (مع طريقة استعادة مجرّبة)، ومراقبة أخطاء ووقت استجابة.
- نقل JWT من `localStorage` إلى جلسة Cookie HttpOnly آمنة قبل الإطلاق الواسع، مع CSRF protection حسب التصميم. تغيير الأسلوب يحتاج ترحيل وتحقق منفصل.
- معالجة تشغيل/معاينة الكود المولّد داخل بيئة معزولة. حالياً **لا يُشغَّل Backend المولّد تلقائياً**؛ يتم تصديره كنص ملفات فقط.
- تقييم التزام المحتوى، شروط مزوّد AI، وتغطية الاختبارات الوظيفية وواجهة الهاتف وإمكانية الوصول.

## ملاحظات الصدق والحدود
- نجاح فحص TypeScript لا يساوي اختبار اختراق أو ضمان عدم وجود ثغرات.
- لا توجد خطة دفع أو نظام اشتراكات/فوترة للمستخدمين في هذا الإصدار.
- لا توجد قاعدة بيانات PostgreSQL في هذا الإصدار؛ يعتمد على SQLite مع تخزين دائم وحالة خدمة واحدة.
